1. 전시 구조 & 우리 팀 작업 흐름

PC 1대에 모든 팀 공간을 모으고, 주제마다 센서가 다르므로 공간(팀)마다 Pico 2 W 를 1대씩 씁니다. 공간을 고르면 그 팀의 Pico 로 자동 연결됩니다.

🖥️ 전시 구성

⛔ 사용 금지 핀

우리가 고른 기본 장치의 핀 + GP23 · GP24 · GP25 · GP29 (Pico 2 W 무선 모듈 내부)

예: "baseDevices": ["sg90"] 이면 GP16 만 예약 → GP15 · GP18~20 · GP26(ADC0) 은 확장 부품에 사용 가능.

Pico 가 팀마다 따로 있으므로 다른 팀과 같은 핀을 써도 됩니다. 대신 Pico IP 는 공간마다 달라야 하며, 겹치면 경고가 뜹니다.

🔌 확장 부품 추천 핀

  • 아날로그 (토양 수분 · 수위 · 가변저항): GP27(ADC1), GP28(ADC2)
  • 디지털 입력 (PIR · 불꽃 · 버튼 · 초음파): GP13 · GP14 · GP17 · GP22
  • 디지털 출력 (릴레이 · 버저 · LED): GP21, GP0 ~ GP12

사용하는 핀은 room.json 의 "pins": ["GP27"] 에 꼭 적습니다.

⚠ RP2350 하드웨어 주의

  • PWM 짝 핀: GP16·GP17, GP18·GP19 는 같은 PWM 이라 둘 다 PWM 으로 쓰면 주파수가 같아야 합니다. SG90(50Hz)을 쓰는 공간에서 GP17 은 디지털 입출력으로 쓰거나, PWM(부저 등)이면 frequency=50
  • 디지털 입력은 Pull.UP: 감지 · 눌림은 value == False 로 판단합니다. RP2350 내부 풀다운 결함(E9) 때문에 Pull.DOWN 은 쓰지 않습니다.

🧪 시뮬레이션 ↔ 우리 팀 Pico

  • 센서 출력 탭에 확장 센서 게이지가 자동으로 생기고 CSV 에도 포함됩니다.
  • 각 파일은 빈 템플릿 · 현재 파일 버튼으로 내려받을 수 있습니다.

baseDevices = 우리 Pico 에 연결하는 기본 장치 · picoIp = 우리 Pico IP (비우면 기존 값 유지). 시뮬레이션/하드웨어 모드는 화면의 Pico 연결 설정에서만 바꿉니다.

Scene.tsx3D 화면
import { Html } from '@react-three/drei';
import { useCustomValue, useServo, sendCommand } from '@/core/sdk';

export default function Scene({ isModalOpen = false }) {
  const weight = useCustomValue('food_weight');
  const { angle } = useServo();
  return (
    <group>
      <mesh onClick={(e) => { e.stopPropagation(); sendCommand('feed', true); }}>
        <boxGeometry args={[0.6, 0.6, 0.6]} />
        <meshStandardMaterial color="#F59E0B" />
      </mesh>
      {!isModalOpen && (
        <Html position={[0, 1, 0]} center zIndexRange={[10, 0]}>
          <div>사료 {weight}g · 뚜껑 {angle}°</div>
        </Html>
      )}
    </group>
  );
}
mock.js시뮬레이션
let weight = 300;
module.exports = {
  tick(state) {
    weight = Math.max(0, weight - Math.random() * 3);
    return { food_weight: Math.round(weight) };
  },
  onCommand(action, value, state) {
    if (action === 'feed') weight = Math.min(500, weight + 50);
    return { food_weight: Math.round(weight) };
  },
};

import analogio

ROOM_ID = "room_mx1abc"
sensor = None

    global sensor

def handle(base, action, value):

base.has('sg90') (code.py)이 Pico 에 그 기본 장치가 연결되어 있는지. 연결 안 된 장치의 base 함수는 None 반환 · 동작 안 함

🧩 baseDevices 에 없는 기본 장치는?

Scene.tsx 에서 그 장치의 SDK(useServo, useRgb, useSensor)를 쓰지 마세요. 대시보드도 그 장치의 게이지 · 제어 버튼을 숨기거나 '미사용'으로 표시합니다.

🔑 key 는 세 곳에서 똑같이

room.json customSensors[].key = mock.js · code.py 가 반환하는 key = Scene.tsx useCustomValue('key'). 다르면 게이지가 계속 '수신 대기'로 보입니다.

🎛️ code.py 가 서보 · LED 를 움직이면 mock.js 도 똑같이

code.py 에서 base.set_servo(90) · base.set_rgb("#EF4444", "ON") 를 쓴다면, mock.js 의 tick/onCommand 도 { servo_angle: 90 } · { rgb_color: '#EF4444', rgb_state: 'ON' } 를 돌려주세요. 그래야 시뮬레이션에서도 3D 화면의 서보 · LED 가 실물과 똑같이 움직입니다.

onCommand(action, value, state) {
  if (action === 'gate') return { servo_angle: value ? 90 : 0 };  // code.py: base.set_servo(90 if value else 0)
}

mock 시나리오의 시간은 state.t(시작 후 지난 초)로 계산합니다 (tick 주기가 브라우저 2초 · mock 서버 1.5초로 달라서 횟수로 세면 틀어짐). "온도가 25~28℃ 를 오르내린다"처럼 기본 센서가 바뀌는 이야기는 tick 이 temperature · humidity · light 를 돌려주면 시뮬레이션의 기본 센서가 그 값이 됩니다. (실제 Pico 에서는 센서가 직접 잽니다)

tick(state) {
  const p = state.t % 40;                                  // 40초 주기
  return { temperature: 26.5 + 1.5 * Math.sin(state.t / 10), noise: p < 20 ? 42 : 65 };
}

6. 아이디어 작성 마스터 클래스 ① — 8가지 원칙과 3D 연출 표현 사전

작품의 수준은 아이디어 칸에 쓴 글이 정합니다. AI 는 우리가 쓴 글만 보고 4개 파일을 한 번에 만들기 때문에, 이 글이 곧 작품의 설계도입니다.

① 장면을 사진처럼 묘사하기

❌ 수족관을 만들어 줘
✅ 바닥 가운데에 가로 3 · 세로 1.5 · 높이 1.8 크기의 투명한 하늘색 유리 수조, 안에 주황색 물고기 5마리와 초록 수초 4개, 오른쪽에 회색 여과기

② 숫자로 말하기

각도 · 기준값 · 주기 · 개수 · 범위를 숫자로 쓰면 AI 가 추측하지 않습니다.

❌ 더우면 창문을 연다
✅ 온도가 28℃ 이상이면 SG90 을 90° 로 열고, 25℃ 이하로 내려가면 0° 로 닫는다

③ "만약 ~이면 ~한다" 규칙 문장

센서 → 판단 → 동작을 한 문장씩 나눠 씁니다. 규칙이 여러 개면 번호를 붙입니다.

✅ 규칙 1: 수위가 20% 미만이면 RGB 빨강 + 배지에 "물 보충 필요"
✅ 규칙 2: 수온이 26℃ 를 넘으면 냉각팬(확장) 작동, 팬 날개가 3D 에서 회전

④ 상태마다 눈에 보이는 변화

관람객은 숫자보다 색 · 움직임을 먼저 봅니다. 정상 / 주의 / 위험 3단계를 정하고 각각 어떻게 보일지 적습니다.

✅ 정상: 초록 + 물고기가 천천히 헤엄 / 주의: 노랑 + 물고기 속도 2배 / 위험: 빨강 깜빡임 + 물고기 멈춤

⑤ 클릭 행동과 결과를 짝짓기

3D 화면에서 무엇을 클릭하면 어떤 명령이 가고 무엇이 바뀌는지 한 줄로 씁니다.

✅ 먹이통을 클릭하면 sendCommand('feed', true) → 먹이 알갱이 10개가 위에서 떨어지고, 3초 뒤 사라짐

⑥ mock 시나리오 = 관람객이 1분 안에 볼 이야기

전시장에서 Pico 없이도 작품이 살아 보이려면, 시뮬레이션 값이 시간에 따라 어떻게 변할지 이야기처럼 적습니다.

✅ 처음 20초는 정상 → 20초부터 수위가 점점 내려가 30초에 경고 → 펌프 명령을 보내면 다시 회복 (40초 주기로 반복)

⑦ 하지 말 것 · 안 쓰는 것 적기

AI 가 엉뚱하게 넣는 것을 미리 막습니다.

✅ DHT11 은 연결하지 않음(baseDevices 에서 제외) · 외부 3D 모델/이미지 파일 사용 금지 · 글자는 Html 배지로만 · 오브젝트는 20개 이하

⑧ 욕심 조절 — 한 번에 다 하지 않기

10. 우리 팀 Pico 2 W 연결하기 (공간마다 1대)

주제마다 센서가 다르므로 팀마다 Pico 를 따로 씁니다. Pico 마다 IP 를 다르게 정하고, 플랫폼의 우리 공간에 그 IP 를 저장하면 공간을 고를 때 자동으로 연결됩니다.

🌐 IP 정하는 2가지 방법

① 고정 IP (권장): 2번에서 저장한 IP 가 settings.toml 의 PICO_STATIC_IP 로 들어갑니다. 공유기와 같은 대역(예: 192.168.0.x) · DHCP 범위 밖 주소를 쓰세요.

PICO_STATIC_IP = "192.168.0.51"
PICO_NETMASK   = "255.255.255.0"   # 생략 가능
PICO_GATEWAY   = "192.168.0.1"     # 생략 시 x.x.x.1
PICO_DNS       = "8.8.8.8"         # 선택 (없어도 됨)

고정 IP 는 Wi-Fi 연결 직후 적용됩니다. 시리얼 창에 고정 IP 적용: 192.168.0.51 이 나오면 성공입니다.

② 공유기 DHCP 예약: PICO_STATIC_IP 줄을 지우고 공유기에서 Pico 에 IP 를 예약 → 시리얼 창의 IP 를 Pico 연결 설정에 입력.

🔁 공간을 바꾸면 자동 전환

  • 공간마다 Pico IP 와 모드(시뮬레이션/하드웨어)가 저장됩니다.
  • 사이드바 공간 아래에 Pico 192.168.0.51 또는 시뮬레이션 표시
  • 상단 시뮬레이션 / Pico 2 W 토글도 지금 공간에만 저장됩니다.
  • 전환 직후 센서는 새 Pico 값이 올 때까지 '수신 대기' 로 보입니다.

Q1. 팀 공간을 다른 PC 로 옮기려면?

플랫폼 폴더의 rooms-data/ 폴더를 통째로 복사하면 됩니다. 각 공간의 파일은 업로드 창의 현재 파일 버튼으로도 내려받을 수 있습니다.

Q1-1. 목록의 '예제' 공간을 고칠 수 있나요?

스마트 거실 허브 · 팜 온실 · 팩토리 · 스마트 독서실은 기본 예제라 이름 변경 · 업로드 · 삭제가 막혀 있습니다. 스마트 독서실은 공간 꾸러미 예제(context/examples/smart_study_room/)라 ⋮ → 공간 복제하기로 사본을 만들면 우리 팀 공간처럼 고쳐 쓸 수 있습니다. Pico 연결 설정은 예제 공간에서도 바꿀 수 있습니다.

Q2. 업로드를 아무나 못 하게 하려면?

전시 PC 에서 ROOM_UPLOAD_KEY=비밀번호 환경변수를 주고 실행합니다. (PowerShell: $env:ROOM_UPLOAD_KEY="1234"; npm start) 학생은 업로드 창에서 비밀번호를 입력합니다.

Q3. Pico 마다 IP 를 어떻게 다르게 정하나요?

① 고정 IP (권장): 공간의 Pico 연결 설정에 IP 를 저장하고 펌웨어를 묶으면 settings.toml 에 PICO_STATIC_IP 가 자동으로 들어갑니다. (공유기 대역 · DHCP 범위 밖 주소)
② 공유기 DHCP 예약: PICO_STATIC_IP 를 지우고 공유기에서 Pico MAC 주소에 IP 를 예약합니다. 시리얼 콘솔의 Pico 2 W IP: 192.168.x.x 를 Pico 연결 설정에 입력합니다.

Q4. 한 팀 code.py 가 고장 나면 전시가 멈추나요?

아니요. Pico 가 팀마다 따로 있어 다른 팀에는 영향이 없고, 그 Pico 도 팀 모듈만 꺼지며 기본 장치와 웹 서버는 계속 동작합니다.

Q5. 모든 공간의 Pico 연결을 한 번에 점검하려면?

대시보드 왼쪽 위 학교 마크를 누르면 '플랫폼 소개 · 전시 현황' 창이 열립니다. 공간마다 하드웨어/시뮬레이션 모드와 Pico IP 가 한눈에 보이고, IP 미지정 · IP 중복은 빨간 경고로 표시됩니다. 행을 누르면 그 공간으로 이동합니다. [첫 화면으로] · [매뉴얼 열기] · [전시 모드 시작] 버튼도 있습니다.

Q6. 전시 중 공유기가 꺼졌다 켜지면?

Pico 펌웨어가 연결 끊김을 알아채고 재연결 → 같은 고정 IP → 서버 재시작을 자동으로 합니다. 1분 정도 기다리면 화면이 다시 연결됨 이 됩니다. 그동안 값은 '수신 대기'로 보입니다.

Q7. Pico 웹 편집기(웹 워크플로)를 쓰고 싶다면?

settings.toml 에 CIRCUITPY_WEB_API_PASSWORD 와 함께 CIRCUITPY_WEB_API_PORT = 8080 을 넣으세요. 80 포트는 플랫폼 서버용이라, 포트를 옮기지 않으면 시리얼 창에 HTTP Server 시작 실패 가 나옵니다.

Q8. 음성 안내를 쓰려면?

전시 PC 에 스피커를 연결하고 왼쪽 메뉴의 🔊 스피커 버튼 → 음성 안내 켜기를 누르세요. 승인 요청 · 제어 동작 · 자동화 스케줄 · Pico 연결 상태를 한국어로 읽어 줍니다. 전시장이 시끄럽거나 안내가 많으면 항목을 골라 끄세요. 브라우저 정책 때문에 새로고침 후에는 화면을 한 번 클릭해야 소리가 납니다. (크롬 · 엣지 권장)

목소리: 크롬에서는 밝은 여성 목소리 'Google 한국의'(온라인 목소리)가 자동으로 선택됩니다. 엣지는 'Microsoft SunHi', 인터넷이 끊기면 윈도우 목소리(Microsoft Heami)로 자동 전환됩니다. 스피커 설정 창의 목소리 · 높낮이 · 속도로 바꿀 수 있고, '지금 목소리'에서 실제 목소리를 확인하세요.

(플랫폼 SDK 의 디자인 킷 PALETTE · MAT · DataPin · HoverLift · useSmoothValue 를 사용합니다)
1. 색: 벽 · 바닥 · 가구 같은 넓은 면은 PALETTE 의 차분한 색(wall, oak, linen, sage, sand, walnut)을 씁니다.
   원색(#FF0000 · #00FF00 · #0000FF) · 순흑(#000) · 순회색은 쓰지 않습니다.
   강조색(PALETTE.ok · warn · alert · info)은 상태 · 데이터 표시에만, 한 화면에 2가지 이하로 씁니다.
2. 재질: 모든 물체에 MAT 프리셋을 씁니다.
   나무 MAT.oak/walnut, 패브릭 MAT.linen/sage, 세라믹 MAT.ceramic, 금속 MAT.brushedMetal, 식물 MAT.plant,
   유리 <meshPhysicalMaterial {...MAT.glass} />. 표시등 · 화면만 MAT.glow(color, on) · MAT.screen(color) 로 빛나게 합니다.
3. 형태 · 비례: 1 = 1m 실제 크기 (책상 높이 0.75, 의자 좌판 0.45, 문 2.0, 천장 3.0).
   가구는 drei RoundedBox(radius 0.03~0.08)로 둥글게, 모든 물체는 바닥이나 벽에 붙게 (공중에 뜨지 않게).
4. 구성: 주인공 오브젝트 1개를 가운데에 두고, 생활감을 주는 소품(화분 · 책 · 쿠션 등) 3~5개를 여백을 두고 배치합니다.
5. 조명: 플랫폼 조명 · 환경광을 그대로 쓰고, pointLight 는 2개 이하로 합니다.
6. 모션: useFrame + THREE.MathUtils.damp 로 감속하며 멈추게 합니다.
   bounce · elastic · 계속 도는 장식은 넣지 않고, 센서 값 · 명령 결과에 반응하는 움직임만 넣습니다.
7. 데이터: 수치는 <DataPin sensor={...} /> 로 통일하고, 배지는 5개 이하 · 서로 겹치지 않게 배치합니다.
   상태는 색 + 글자로 함께 보여 줍니다.
8. 상호작용: 클릭할 물체는 <HoverLift onClick={...}> 로 감싸고 sendCommand 를 연결합니다.
9. 견고성: 센서 값으로 움직이는 부분은 useSmoothValue 로 부드럽게 합니다 (끊기면 마지막 값 유지).
10. 성능: useFrame 안에서 new THREE.Vector3() 등 객체를 만들지 않습니다.
    같은 물체 10개 이상은 drei <Instances> 로, 전체 오브젝트는 80개 이하로 합니다.
    외부 모델 · 텍스처 · drei Text 는 쓰지 않고, 글자는 <Html> 로 씁니다.

예시 코드 (수족관 수조)킷 함께 쓰기
import React, { useRef } from 'react';
import * as THREE from 'three';
import { useFrame } from '@react-three/fiber';
import { RoundedBox } from '@react-three/drei';
import { MAT, PALETTE, DataPin, HoverLift, useSmoothValue, useCustomSensor, sendCommand } from '@/core/sdk';

export default function Scene({ isModalOpen = false }: { isModalOpen?: boolean }) {
  const level = useCustomSensor('water_level');          // 0~100 %
  const smooth = useSmoothValue(level?.value, { initial: 50 });
  const water = useRef<THREE.Mesh>(null);
  useFrame(() => {
    if (!water.current) return;
    const k = THREE.MathUtils.clamp(smooth.current / 100, 0.05, 1); // 범위 밖 값은 잘라서
    water.current.scale.y = k;
    water.current.position.y = 0.45 + (1.2 * k) / 2;
  });
  return (
    <group>
      <mesh rotation={[-Math.PI / 2, 0, 0]} receiveShadow>
        <planeGeometry args={[7, 7]} /><meshStandardMaterial {...MAT.oak} />
      </mesh>
      <RoundedBox args={[2.4, 0.45, 1.2]} radius={0.05} position={[0, 0.225, 0]} castShadow>
        <meshStandardMaterial {...MAT.walnut} />
      </RoundedBox>
      <mesh ref={water} position={[0, 1.05, 0]}>
        <boxGeometry args={[2.2, 1.2, 1.0]} />
        <meshStandardMaterial color={PALETTE.info} transparent opacity={0.35} roughness={0.1} />
      </mesh>
      <mesh position={[0, 1.05, 0]}>
        <boxGeometry args={[2.3, 1.25, 1.1]} /><meshPhysicalMaterial {...MAT.glass} />
      </mesh>
      <HoverLift position={[1.5, 0.45, 0]} onClick={() => sendCommand('feed', true)}>
        <mesh castShadow><cylinderGeometry args={[0.12, 0.12, 0.25, 32]} /><meshStandardMaterial {...MAT.ceramic} /></mesh>
      </HoverLift>
      <DataPin position={[-1.4, 0.45, 0.4]} label="수위" sensor={level} isModalOpen={isModalOpen} />
    </group>
  );
}

⚡ 성능 규칙 (느린 전시 PC 대비)

  • 전체 오브젝트 80개 이하, pointLight 2개 이하, 그림자는 큰 물체에만
