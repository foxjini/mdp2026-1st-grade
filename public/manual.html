STEP 01 · EXHIBITION & WORKFLOW

1. 전시 구조 & 우리 팀 작업 흐름

PC 1대에 모든 팀 공간을 모으고, 주제마다 센서가 다르므로 공간(팀)마다 Pico 2 W 를 1대씩 씁니다. 공간을 고르면 그 팀의 Pico 로 자동 연결됩니다.

🖥️ 전시 구성

  • 윈도우 PC 1대 + 모니터 (이 플랫폼 실행)
  • 공간마다 Pico 2 W 1대 (IP 가 서로 다름, 예: 192.168.0.51 · .52 · .53)
  • 기본 장치 4종(DHT11 · Cds · SG90 · RGB LED) 중 우리 팀이 고른 것
  • 팀 확장 부품 (토양 수분 센서, 릴레이 등)

🧩 팀 = 공간 하나

왼쪽 사이드바의 '새 공간 추가'로 팀 공간을 만들고, 4개 파일(공간 꾸러미)을 업로드합니다.

  • room.json 공간 정보 · 확장 센서
  • Scene.tsx 3D 화면
  • mock.js 시뮬레이션
  • code.py Pico 2 W 팀 모듈

⚡ 업로드 = 즉시 적용

업로드하면 빌드 없이 바로 3D 화면에 나타납니다. 오류가 있어도 우리 팀 공간에만 빨간 배지가 뜨고 다른 팀 공간은 정상입니다.

  • 플랫폼 원본(src/, firmware/)은 수정 금지
  • 하드웨어 없이 시뮬레이션으로 연습

STEP 02 · BASE DEVICES & PINS

2. 기본 장치 고르기 & 확장 핀 규칙

우리 팀 Pico 에 연결할 기본 장치만 baseDevices 로 고릅니다. 고른 장치는 주제에 맞게 '의미'를 바꿔 쓰고, 추가 부품은 빈 핀에 연결합니다.

장치 (baseDevices 값)핀 (변경 금지)Scene.tsx 에서code.py 에서재해석 예시
DHT11 온습도 dht11GP15useSensor('dht11_temp')
useSensor('dht11_humi')		base.temperature()
base.humidity()		온실 온도, 불쾌지수 계산
Cds 조도 cdsGP26 (ADC0)useSensor('cds_light') 0~65535base.light()밤/낮 판단, 물품 통과 감지
SG90 서보 sg90GP16useServo() → angle, setAnglebase.set_servo(90)환기 돔, 급식기 뚜껑, 차단기
RGB LED rgbGP18 · GP19 · GP20useRgb() → color, onbase.set_rgb("#FF0000", "ON")생장등, 경보등, 타워 램프

⛔ 사용 금지 핀

우리가 고른 기본 장치의 핀 + GP23 · GP24 · GP25 · GP29 (Pico 2 W 무선 모듈 내부)

예: "baseDevices": ["sg90"] 이면 GP16 만 예약 → GP15 · GP18~20 · GP26(ADC0) 은 확장 부품에 사용 가능.

Pico 가 팀마다 따로 있으므로 다른 팀과 같은 핀을 써도 됩니다. 대신 Pico IP 는 공간마다 달라야 하며, 겹치면 경고가 뜹니다.

🔌 확장 부품 추천 핀

  • 아날로그 (토양 수분 · 수위 · 가변저항): GP27(ADC1), GP28(ADC2)
  • 디지털 입력 (PIR · 불꽃 · 버튼 · 초음파): GP13 · GP14 · GP17 · GP22
  • 디지털 출력 (릴레이 · 버저 · LED): GP21, GP0 ~ GP12

사용하는 핀은 room.json 의 "pins": ["GP27"] 에 꼭 적습니다.

STEP 03 · ADD ROOM & UPLOAD

3. 새 공간 추가 → AI 프롬프트 복사 → 업로드

대시보드 화면에서 실제로 누르는 버튼 순서입니다.

1️⃣ 새 공간 추가 (1/2 공간 정보)

  1. 왼쪽 사이드바 + 새 공간 추가 클릭
  2. 공간 이름 (예: 스마트 펫룸), 팀 이름 (예: 1학년 3반 2팀), 설명, 아이콘 입력
  3. 우리 팀 Pico 에 연결할 기본 장치 체크 (연결 안 하는 장치는 체크 해제)
  4. 우리 팀 Pico 2 W IP (아직 Pico 가 없으면 비워 두기 → 시뮬레이션)
  5. [공간 생성 후 코드 업로드 →] 클릭 → 공간 ID (예: room_mx1abc) 발급

나중에 다시 열 때: 공간 오른쪽 ⋮ → 코드 업로드 · 관리 / ⋮ → Pico 연결 설정

2️⃣ 코드 업로드 창 (2/2)

  1. ① 아이디어 작성 칸에 STEP 05 공식대로 우리 팀 아이디어 입력
  2. [AI 프롬프트 복사] → AI 채팅창에 붙여넣기 (마스터 컨텍스트 + 공간 ID 자동 포함)
  3. AI 답변의 코드 블록 4개를 파일로 저장 (room.json · Scene.tsx · mock.js · code.py)
  4. ③ 업로드에 파일을 끌어다 놓기 · 또는 직접 붙여넣기에서 파일 종류 선택 후 붙여넣기
  5. [닫고 3D 화면 확인]

✅ 업로드 전 자동 검사

  • Scene.tsx: 문법 · 허용 모듈 · export default 확인
  • mock.js: 실행 가능 여부 확인
  • room.json: JSON 형식 · key · 핀 형식 확인

오류가 있으면 업로드하지 않고 빨간 메시지를 보여 줍니다. 그 메시지를 그대로 AI 에게 보내세요.

🧪 시뮬레이션 ↔ 우리 팀 Pico

  • 모드와 Pico IP 는 공간마다 저장됩니다. 공간을 고르면 그 설정으로 자동 연결 (상단 헤더에 Pico 2 W 192.168.0.51 · 연결됨)
  • 시뮬레이션 모드: mock.js 가 확장 센서 값을 만듭니다.
  • Pico 없이 하드웨어 모드 연습: npm run mock:pico -- --room 공간ID --port 5051 → Pico 연결 설정에 127.0.0.1:5051
  • 센서 출력 탭에 확장 센서 게이지가 자동으로 생기고 CSV 에도 포함됩니다.
  • 각 파일은 빈 템플릿 · 현재 파일 버튼으로 내려받을 수 있습니다.

Scene.tsx3D 화면
import { Html } from '@react-three/drei';
import { useCustomValue, useServo, sendCommand } from '@/core/sdk';

export default function Scene({ isModalOpen = false }) {
  const weight = useCustomValue('food_weight');
  const { angle } = useServo();
  return (
    <group>
      <mesh onClick={(e) => { e.stopPropagation(); sendCommand('feed', true); }}>
        <boxGeometry args={[0.6, 0.6, 0.6]} />
        <meshStandardMaterial color="#F59E0B" />
      </mesh>
      {!isModalOpen && (
        <Html position={[0, 1, 0]} center zIndexRange={[10, 0]}>
          <div>사료 {weight}g · 뚜껑 {angle}°</div>
        </Html>
      )}
    </group>
  );
}
mock.js시뮬레이션
let weight = 300;
module.exports = {
  tick(state) {
    weight = Math.max(0, weight - Math.random() * 3);
    return { food_weight: Math.round(weight) };
  },
  onCommand(action, value, state) {
    if (action === 'feed') weight = Math.min(500, weight + 50);
    return { food_weight: Math.round(weight) };
  },
};
code.pyPico 팀 모듈
import board
import analogio

ROOM_ID = "room_mx1abc"
sensor = None

def setup(base):
    global sensor
    sensor = analogio.AnalogIn(board.GP27)

def read(base):
    return {"food_weight": round(sensor.value / 65535 * 500)}

def handle(base, action, value):
    if action == "feed":
        base.set_servo(90)
        return {"ok": True}
    return {"ok": False}
SDK (@/core/sdk)설명
useSensor('dht11_temp' | 'dht11_humi' | 'cds_light')기본 센서 { value, unit, isStale }
useCustomValue(key, 기본값) / useCustomSensor(key)room.json 확장 센서 값
useServo() / useRgb()SG90 { angle, setAngle } · RGB { color, on, setColor, setOn }
sendCommand(action, value)시뮬레이션 → mock.js onCommand / 하드웨어 → code.py handle

🔑 key 는 세 곳에서 똑같이

room.json customSensors[].key = mock.js · code.py 가 반환하는 key = Scene.tsx useCustomValue('key'). 다르면 게이지가 계속 '수신 대기'로 보입니다.

STEP 06 · TOPIC EXAMPLES

6. 주제별 아이디어 예시 6선 (복사해서 아이디어 칸에)

그대로 써도 되고, 우리 팀 상황에 맞게 고쳐 써도 됩니다. 스마트팜 완성본은 context/examples/smart_farm/ 에 있습니다.

1. 스마트 팜 온실완성 예제 있음
[주제] 토양이 마르면 자동으로 물을 주는 스마트 팜 온실
[기본 장치 역할] SG90 = 온실 환기 돔(0° 닫힘 ~ 180° 최대 개방), RGB LED = 식물 생장등, DHT11 = 온실 온습도
[확장 센서] key: soil_moisture / 토양 수분 / % / 0~100 / 핀 GP27 (ADC1), 35% 미만이면 경고
[확장 센서] key: pump_on / 관수 펌프 상태 / 0·1 / 핀 GP21 (릴레이)
[확장 동작] 펌프를 클릭하면 sendCommand('water', true/false) 로 펌프를 켜고 끈다
[3D 장면] 유리 온실, 화분 배드와 식물 5그루, 환기 돔, 관수 펌프. 수분이 낮으면 흙 색이 밝아지고 잎이 누렇게 변한다
[mock 규칙] 수분은 천천히 줄고, 펌프가 켜지면 빠르게 오르며 80% 이상이면 펌프가 자동으로 꺼진다
2. 스마트 팩토리 분류 라인SG90 푸셔
[주제] 컨베이어 위 불량품을 밀어내는 스마트 팩토리
[기본 장치 역할] SG90 = 불량품 푸셔 암(0° 대기 / 60° 밀어내기), RGB LED = 타워 램프(초록 가동 / 노랑 대기 / 빨강 정지), Cds = 물품 통과 감지
[확장 센서] key: product_count / 생산 수량 / 개 / 0~999 (센서 없음: code.py 에서 Cds 값이 갑자기 낮아질 때 1 증가)
[확장 동작] 비상정지 버튼을 클릭하면 sendCommand('estop', true) → RGB 빨강, 컨베이어 정지
[3D 장면] 금속 컨베이어 벨트 위를 상자가 계속 지나가고, 푸셔 암이 서보 각도에 맞춰 움직인다
[mock 규칙] 2초마다 product_count 가 0~2 증가, estop 중에는 증가하지 않음
3. 스마트 주차장초음파 센서
[주제] 빈자리를 알려 주는 스마트 주차장
[기본 장치 역할] SG90 = 차단기(0° 닫힘 / 90° 열림), RGB LED = 만차 표시(초록 빈자리 / 빨강 만차)
[확장 센서] key: distance_cm / 차량 거리 / cm / 0~200 / 핀 GP13(Echo), GP14(Trig)  ※ adafruit_hcsr04 라이브러리 필요 → 선생님께 확인
[확장 센서] key: occupied / 주차 여부 / 0·1 (distance_cm 30 미만이면 1)
[확장 동작] 차단기를 클릭하면 sendCommand('gate', true)
[3D 장면] 주차칸 3개, 차량 박스가 거리 값에 따라 앞뒤로 이동, 차단기 막대 회전
[mock 규칙] 차량이 10초 주기로 들어왔다 나간다 (state.t 사용)
4. 화재 · 방재 안전실불꽃 감지
[주제] 온도가 오르면 경보를 울리고 비상문을 여는 방재 안전실
[기본 장치 역할] DHT11 = 실내 온도, SG90 = 비상 탈출문, RGB LED = 경보등(평상시 흰색, 35℃ 이상 빨강)
[확장 센서] key: flame / 불꽃 감지 / 0·1 / 핀 GP17 (디지털 입력)
[확장 동작] 경보 해제 버튼 클릭 → sendCommand('reset', true)
[3D 장면] 복도와 비상문, 천장 스프링클러, 불꽃 감지 시 빨간 파티클(작은 구체 여러 개)
[mock 규칙] 30초에 한 번 flame 이 1이 되었다가 reset 명령이 오면 0
5. 스마트 펫룸무게 센서

8. 전시 당일 체크리스트 (교사용) & FAQ

PC 1대에 모든 팀 공간을 모으고, 공간마다 Pico 2 W 1대를 연결합니다. Pico 마다 IP 가 달라야 합니다.

순서할 일명령 / 위치
1전시 PC 에서 플랫폼 실행npm run build → npm start → http://localhost:3001
2각 팀 공간을 하나씩 열어 오류 배지가 없는지 확인왼쪽 공간 목록
3공간마다 Pico IP 정하기 (예: 팜 .51, 공장 .52 …) → 각 공간 ⋮ → Pico 연결 설정에 저장npm run firmware:bundle 로 공간 ID · IP 목록 확인
4Pico 를 하나씩 USB 로 연결해 그 공간 펌웨어 설치 (핀 충돌 · 문법 검사 · 고정 IP 포함)npm run firmware:bundle -- 공간ID E:\ (E: = 그 Pico 의 CIRCUITPY)
5settings.toml 에 전시장 Wi-Fi 입력, lib/ 라이브러리 확인 (스크립트가 필요 lib 안내)CIRCUITPY 드라이브
6재부팅 후 공간 · 기본 장치 · 팀 모듈 확인http://<Pico IP>/api/teams
7공간을 하나씩 선택해 헤더가 Pico 2 W <IP> · 연결됨 인지 확인 → 전시 모드상단 헤더

💡 3D UI 레이어링 2대 원칙

  1. Drei <Html> zIndexRange 제한: 모든 3D 배지에 zIndexRange={[10, 0]} (모달 z-[100] 위로 뚫고 나오지 않게)
  2. 모달이 열리면 숨기기: {!isModalOpen && <Html>...</Html>}

Q1. 팀 공간을 다른 PC 로 옮기려면?

플랫폼 폴더의 rooms-data/ 폴더를 통째로 복사하면 됩니다. 각 공간의 파일은 업로드 창의 현재 파일 버튼으로도 내려받을 수 있습니다.

Q2. 업로드를 아무나 못 하게 하려면?

전시 PC 에서 ROOM_UPLOAD_KEY=비밀번호 환경변수를 주고 실행합니다. (PowerShell: $env:ROOM_UPLOAD_KEY="1234"; npm start) 학생은 업로드 창에서 비밀번호를 입력합니다.

Q3. Pico 마다 IP 를 어떻게 다르게 정하나요?

① 고정 IP (권장): 공간의 Pico 연결 설정에 IP 를 저장하고 펌웨어를 묶으면 settings.toml 에 PICO_STATIC_IP 가 자동으로 들어갑니다. (공유기 대역 · DHCP 범위 밖 주소)
② 공유기 DHCP 예약: PICO_STATIC_IP 를 지우고 공유기에서 Pico MAC 주소에 IP 를 예약합니다. 시리얼 콘솔의 Pico 2 W IP: 192.168.x.x 를 Pico 연결 설정에 입력합니다.

Q4. 한 팀 code.py 가 고장 나면 전시가 멈추나요?

아니요. Pico 가 팀마다 따로 있어 다른 팀에는 영향이 없고, 그 Pico 도 팀 모듈만 꺼지며 기본 장치와 웹 서버는 계속 동작합니다.
