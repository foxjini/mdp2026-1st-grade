# 개별 프로젝트 제작 과정 영상 — 내레이션 대본

스마트 버스정류장 쉼터를 매뉴얼 9단계로 만드는 영상입니다. 영상은 무음이며, 화면 자막을 그대로 읽거나 아래 대본으로 녹음해 덧입힐 수 있습니다.
자막 파일(`개별프로젝트_제작과정.srt`)을 플레이어에서 켜면 같은 문장이 나옵니다.

> AI 대화 장면은 실제로 AI 와 나눈 대화를 그대로 보여 주는 재현 화면이고, Pico 는 실제 펌웨어를 실행하는 가상 Pico 로 시연했습니다.

## 인트로 · 9단계 한눈에  (00:00:00)

**화면:** 제목 카드 → 매뉴얼 첫 장(9단계 지도)

- `00:00:00` 매뉴얼 9단계를 실제 프로젝트로 처음부터 끝까지 따라 해 봅니다
- `00:00:04` 매뉴얼 첫 장: 이 9단계를 순서대로 진행합니다
- `00:00:08` 가장 중요한 단계는 ④ 아이디어 쓰기 — AI 는 우리가 쓴 글대로 만듭니다
- `00:00:12` 규칙은 숫자로, 오류는 그대로 복사, 고칠 때는 조금씩

## ① 주제 정하기  (00:00:16)

**화면:** ① 카드 → 매뉴얼 ① → 우리 팀 주제 한 문장

- `00:00:19` 매뉴얼 ①: 누가 · 어디서 · 어떤 불편을 겪는지 생각합니다
- `00:00:24` 불편: 춥고, 밤에는 어둡고, 버스가 언제 오는지 모른다
- `00:00:29` ✅ 한 문장으로 말할 수 있으면 ① 완료!

## ② 부품 · 핀 정하기  (00:00:31)

**화면:** ② 카드 → 매뉴얼 ② 표 + 부품 메모

- `00:00:34` 기본 장치 4종의 핀은 고정입니다. 우리 주제에 쓸 것만 고릅니다
- `00:00:39` 메모: 온도 · 조도 · RGB 는 쓰고, 서보는 안 씀 + 확장 부품 2개
- `00:00:44` ⚠ 진짜 히터처럼 뜨거운 · 고전압 부품은 금지 → LED 로 표시합니다

## ③ 새 공간 추가  (00:00:48)

**화면:** 대시보드 [+ 새 공간 추가] 실제 조작

- `00:00:55` 3D 대시보드 왼쪽 목록에서 [+ 새 공간 추가]
- `00:01:03` 공간 이름 · 팀 이름 · 한 줄 설명을 씁니다
- `00:01:16` ② 메모대로 기본 장치를 고릅니다 — 안 쓰는 SG90 서보는 끄기
- `00:01:23` Pico IP 는 비워 둡니다 (⑦ 단계에서 입력)
- `00:01:30` ✅ 목록에 우리 공간이 생기고, 코드 업로드 창이 열립니다

## ④ 아이디어 쓰기 + AI 프롬프트 복사  (00:01:34)

**화면:** 매뉴얼 부록 A 팀 정보 카드 입력

- `00:01:34` 빈칸 채우기가 어렵다면 매뉴얼 부록 A — 팀 정보 카드만 쉬운 말로 채웁니다
- `00:01:50` 모르는 칸은 "추천해 주세요" 라고 써도 됩니다
- `00:01:53` [도우미 프롬프트 만들기 · 복사] → AI 새 대화창 ① 에 붙여넣기

**화면:** AI 대화창 ① (실제 대화 재현): 질문 → 답 → 완성된 아이디어

- `00:01:57` AI 가 바로 만들지 않고, 모르는 것을 먼저 질문합니다
- `00:02:01` 추천과 보기(①②③)가 있어 고르기만 하면 됩니다 — 사람 감지는 PIR 을 GP14 에
- `00:02:05` 번호로 답하고 "빈칸 없이 완성" 을 부탁합니다
- `00:02:11` ✅ 숫자가 들어간 완성된 아이디어 — 22℃ 미만 · 조도 25000 미만 · 초록 #22C55E

**화면:** 코드 업로드 창: 아이디어 붙여넣기 → [AI 프롬프트 복사]

- `00:02:15` 코드 업로드 창 ① 아이디어 작성 칸에 완성된 아이디어를 붙여넣기 (Ctrl + V)
- `00:02:19` [AI 프롬프트 복사] — 플랫폼 규격 + 우리 공간 정보 + 아이디어가 함께 복사됩니다
- `00:02:26` ✅ 복사 완료 → 이제 AI 새 대화창 ② 에 붙여넣습니다

## ⑤ 바이브 코딩  (00:02:29)

**화면:** AI 대화창 ② (실제 대화 재현): 파일 4개 받기 → 저장

- `00:02:31` 새 대화창에 Ctrl + V — 규격 · 공간 ID · 아이디어가 한 번에 들어갑니다
- `00:02:50` AI 가 설계 요약과 함께 코드 블록 4개를 줍니다: room.json · Scene.tsx · mock.js · code.py
- `00:02:53` ✅ 확인: 파일 4개 · 센서 key(person · bus_eta · heater) 가 모든 파일에서 같은 이름
- `00:02:59` 코드 블록마다 복사 → 메모장에 붙여넣기 → 정확한 파일 이름으로 저장

## ⑥ 업로드 · 시뮬레이션 확인  (00:03:03)

**화면:** 파일 4개 끌어다 놓기 → 3D 화면 · 센서 출력 확인

- `00:03:12` 공간 메뉴 ⋮ → 코드 업로드 · 관리
- `00:03:23` 저장한 파일 4개를 끌어다 놓기
- `00:03:29` 업로드 결과 확인 — 빨간 오류가 없으면 [닫고 3D 화면 확인]
- `00:03:41` 확인 ① 3D 화면에 우리 장면이 보인다 (빨간 오류 배지 없음)
- `00:03:50` 확인 ② 센서 출력 탭: 사람 감지 · 버스 도착 · 히터 값이 바뀐다
- `00:03:55` 첫 결과는 동작은 OK! 하지만 정류장이 너무 크고 버스가 안 보입니다 → 마지막에 UI/UX 개선

## ⑦ 배선 · Pico 연결  (00:04:04)

**화면:** 배선 목록 → 펌웨어 설치 터미널 → Pico 연결 설정 → 연결됨

- `00:04:06` 부품은 AI 가 정한 핀(GP14 · GP21)에 연결합니다
- `00:04:09` Pico 를 USB 로 꽂고, 선생님이 펌웨어 설치 명령을 실행합니다
- `00:04:15` ✅ "핀 충돌 / 문법 오류 없음" → settings.toml 에 Wi-Fi 입력 후 재부팅
- `00:04:19` 시리얼 창에 나온 Pico IP 를 적어 둡니다 (영상은 가상 Pico 로 시연)
- `00:04:32` 공간 메뉴 ⋮ → Pico 연결 설정
- `00:04:43` Pico IP 입력 → [Pico 2 W 연결 저장] (수업: 192.168.x.x / 영상: 가상 Pico)
- `00:04:57` ✅ 화면 위쪽이 Pico 2 W · 연결됨 — 이제 진짜 센서 값입니다
- `00:05:05` PIR 앞에서 손을 흔들면 → 사람 감지 1, 추워서(19℃) 히터 LED 켜짐

## ⑧ 자동화 규칙 점검  (00:05:16)

**화면:** 📅 자동화 스케줄: 서보 규칙 건너뜀 · 취침 모드 끄기

- `00:05:20` 3D 화면 오른쪽 아래 📅 자동화 스케줄
- `00:05:27` 서보가 없는 공간이라 서보 규칙은 "건너뜀" — 플랫폼이 알려 줍니다
- `00:05:32` 밤 11시 무드등 보라색은 정류장과 안 맞으니 끄기 (켜기/끄기는 이 공간에만)
- `00:05:40` 우리 팀만의 자동 동작(사람 + 추위 → 히터)은 이미 ④ 아이디어의 [규칙]으로 code.py 에 들어 있습니다

## UI/UX 개선 (부록 B)  (00:05:44)

- `00:05:48` 부록 B ②: 다듬기 → 모션 → 견고성 → 감탄 포인트 → 셀프 리뷰 순서로 하나씩
- `00:05:53` 먼저 화면에서 아쉬운 점을 적고, 부록 B ① 다듬기 프롬프트를 붙입니다
- `00:06:08` AI 가 고친 점 요약 + Scene.tsx 전체 — 바닥 12m → 7.4m, 버스 대기, 오크 벤치 · 소품 4개
- `00:06:19` 고친 Scene.tsx 하나만 다시 끌어다 놓기
- `00:06:31` 정류장이 화면에 쏙 · 버스가 보이고 · 벤치는 나무 + 방석으로

**화면:** ④ 감탄 포인트 프롬프트 → 마스코트 · 빛 고리 확인

- `00:06:36` 다음은 부록 B ④ 감탄 포인트 — 데이터와 연결된 "와!" 1~2개
- `00:06:49` 히터가 켜지는 순간 빛 고리, 버스 1분 전 표지판 초록 빛, 인도를 걷는 학생 마스코트
- `00:07:01` 다시 Scene.tsx 업로드 → 확인
- `00:07:13` 학생 마스코트가 정류장 앞을 천천히 걷고, 값이 바뀌는 순간 연출이 한 번 일어납니다
