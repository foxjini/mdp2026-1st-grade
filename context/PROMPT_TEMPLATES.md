## 1-1. 아이디어 작성 8가지 원칙 (매뉴얼 STEP 06 요약)

우리 방식(컨텍스트 엔지니어링)에서는 AI 가 **우리가 붙여 넣은 글만** 보고 4개 파일을 한 번에 만듭니다. 빈칸은 AI 가 평범한 상상으로 채우므로, 아이디어 글이 곧 작품의 설계도입니다.

| # | 원칙 | ❌ 막연하게 | ✅ 구체적으로 |
| :--- | :--- | :--- | :--- |
| 1 | 장면을 사진처럼 | 수족관을 만들어 줘 | 바닥 가운데 가로 3 · 높이 1.8 투명 하늘색 수조, 주황 물고기 5마리, 초록 수초 4개 |
| 2 | 숫자로 말하기 | 더우면 창문을 연다 | 28℃ 이상이면 SG90 90°, 25℃ 이하면 0° |
| 3 | "만약 ~이면 ~한다" 규칙 | 물이 부족하면 알려 줘 | 규칙 1: 수위 20% 미만이면 RGB 빨강 + 배지 "물 보충 필요" |
| 4 | 상태마다 보이는 변화 | 경고를 보여 줘 | 정상 초록 · 주의 노랑 + 물고기 속도 2배 · 위험 빨강 깜빡임 |
| 5 | 클릭과 결과를 짝짓기 | 먹이를 줄 수 있게 | 먹이통 클릭 → sendCommand('feed', true) → 알갱이 10개가 떨어지고 3초 뒤 사라짐 |
| 6 | mock = 1분짜리 이야기 | 값이 변하게 | 20초 정상 → 30초에 경고 → 펌프 명령으로 회복, 40초 주기 반복 |
| 7 | 하지 말 것 적기 | (없음) | DHT11 연결 안 함 · 외부 모델 금지 · 오브젝트 20개 이하 |
| 8 | 욕심 조절 · 3단계 | 한 번에 전부 | 1차 뼈대 → 2차 모양 → 3차 연출 |

**3D 연출 표현 사전:** 회전(문 · 뚜껑 · 팬) · 이동(컨베이어 · 차량) · 크기/높이 변화(물 높이 · 식물 성장) · 색 변화(온도 파랑→빨강) · 발광/깜빡임(경고등) · 파티클(불꽃 · 물방울 · 먹이) · 흔들림(꼬리 · 잎) · 숫자 배지(Html) · 조명(RGB 색)

## 2. 주제별 아이디어 예시 (그대로 붙여 넣어도 됩니다)

> 공간마다 Pico 가 따로 있으므로 예시마다 쓰는 기본 장치가 다릅니다. **[기본 장치 역할]에 없는 기본 장치는 연결하지 않는 것**으로 보고 `baseDevices` 에서 빼 달라고 AI 에게 요청하세요.

### 2-1. 스마트 팜 온실
```text
[주제] 토양이 마르면 자동으로 물을 주는 스마트 팜 온실
[사용 기본 장치] dht11, cds, sg90, rgb (4종 모두)
[기본 장치 역할] SG90 = 온실 환기 돔(0° 닫힘 ~ 180° 최대 개방), RGB LED = 식물 생장등, DHT11 = 온실 온습도
[확장 센서] key: soil_moisture / 토양 수분 / % / 0~100 / 핀 GP27 (ADC1), 35% 미만이면 경고
[확장 센서] key: pump_on / 관수 펌프 상태 / 0·1 / 핀 GP21 (릴레이)
[확장 동작] 펌프를 클릭하면 sendCommand('water', true/false) 로 펌프를 켜고 끈다
[3D 장면] 유리 온실, 화분 배드와 식물 5그루, 환기 돔, 관수 펌프. 수분이 낮으면 흙 색이 밝아지고 잎이 누렇게 변한다
[mock 규칙] 수분은 천천히 줄고, 펌프가 켜지면 빠르게 오르며 80% 이상이면 펌프가 자동으로 꺼진다
```
> 이 예시로 만든 완성본이 `context/examples/smart_farm/` 에 있습니다.

```text
[확장 센서] key: product_count / 생산 수량 / 개 / 0~999 (센서 없음: code.py 에서 Cds 값이 갑자기 낮아질 때 1 증가)

[mock 규칙] 2초마다 product_count 가 0~2 증가, estop 중에는 증가하지 않음
```

### 2-7. 나쁜 예 vs 좋은 예 (스마트 수족관)
❌ 나쁜 예: "스마트 수족관을 만들고 싶어요. 온도 센서랑 수위 센서를 쓰고, 물이 부족하면 알려 주세요. 3D 로 멋있게 만들어 주세요."

✅ 좋은 예:
```text
[주제] 집을 비워도 물고기를 지켜 주는 스마트 수족관
[사용 기본 장치] dht11(수조 옆 실내 온도), sg90(먹이통 뚜껑), rgb(수조 조명) / cds 는 연결 안 함
[확장 센서] key: water_level / 수위 / % / 0~100 / GP27 (ADC1), 20% 미만 경고
[규칙]
1. 수위가 20% 미만이면 RGB 빨강, 배지에 "물 보충 필요"
2. 수위가 20~50% 이면 RGB 노랑, 50% 이상이면 RGB 하늘색
3. 먹이통을 클릭하면 sendCommand('feed', true) → SG90 90° 로 3초 열렸다 닫힘
[3D 장면]
- 바닥 가운데: 가로 3 · 높이 1.8 · 깊이 1.5 투명 하늘색 유리 수조 (opacity 0.25)
- 수조 안: 수위만큼 높이가 변하는 파란 물 덩어리, 주황 물고기 5마리(타원 몸통 + 삼각 꼬리)가 원을 그리며 헤엄
- 수조 바닥: 모래색 바닥과 초록 수초 4개(위아래로 살랑살랑)
- 수조 위 오른쪽: 노란 원통 먹이통 + 뚜껑(SG90), 열리면 갈색 먹이 알갱이 10개가 떨어짐
- 수조 위: "수위 80% · 실내 24℃" Html 배지, 경고면 배경 빨강
[mock 규칙] 수위는 100% 에서 시작해 1초에 1%씩 증발, 30% 아래가 되면 15초 뒤 다시 100% 로 채워짐(물 보충)
[하지 말 것] 외부 3D 모델·이미지 금지, 오브젝트 25개 이하, Cds 사용 금지
```

### 2-8. 완성 예시문 A — 스마트 교실 에너지 지킴이
```text
[주제] 아무도 없는 교실의 전기 낭비를 막는 에너지 지킴이
[사용 기본 장치] cds(창밖 밝기), sg90(블라인드 각도), rgb(천장 조명) / dht11 연결 안 함
[확장 센서] key: people / 재실 인원 / 명 / 0~30 / GP14 (PIR 동작 감지, 감지 횟수로 추정)
[확장 센서] key: power_w / 사용 전력 / W / 0~2000 (센서 없음: 조명·블라인드 상태로 계산)
[규칙]
1. people 이 0 이면 10초 뒤 조명 OFF, 배지에 "빈 교실 · 절전 중"
2. 창밖이 밝으면(cds 40000 이상) 조명을 따뜻한 흰색 50% 느낌의 연한 노랑, 어두우면 밝은 흰색
3. 햇빛이 아주 강하면(cds 55000 이상) 블라인드 SG90 60° 로 내림
4. 칠판 옆 스위치를 클릭하면 sendCommand('lights', true/false)
[3D 장면] 책상 3줄×4개(갈색) · 의자 · 앞쪽 초록 칠판 · 오른쪽 창문 3개와 블라인드 날개 8개(SG90 각도만큼 회전)
· 사람이 있는 책상에는 파란 원기둥 학생 모형 · 칠판 위 "사용 전력 420W" 배지(1000W 넘으면 빨강)
[mock 규칙] 수업(30초, 인원 20~28명) → 쉬는 시간(10초, 인원 0~3명) → 빈 교실(15초, 0명) 반복
[하지 말 것] 외부 모델 금지, 학생 모형은 단순 도형, 오브젝트 40개 이하(책상은 map 으로 반복)
```

### 2-9. 완성 예시문 B — 스마트 무인 택배함

```text
[확장 센서] key: wait_min / 가장 오래 보관된 시간 / 분 / 0~120, 60 이상 경고

```
